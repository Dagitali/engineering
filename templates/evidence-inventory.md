# Evidence Inventory Template

Use for a material technical, compatibility, quantitative, or release claim requiring a fuller
evidence record. This is not a mandatory gate for every documentation edit. Keep confidential
completed records in access-controlled storage; this repository retains the blank form.

## Candidate Claim

| Field | Record |
| --- | --- |
| Claim and intended audience/surface | |
| Evidence owner and source location | |
| Category: source, test, artifact, hosted result, consumer report, primary source | |
| Public or private | |
| Exact revision, tag, artifact, or observation time | |

## Authority and Disclosure

| Question | Record |
| --- | --- |
| Who owns the material and can authorize disclosure? | |
| Which names, quotes, screenshots, identifiers, or architectural details may be included? | |
| Which facts must remain private? | |
| Could wording imply unsupported endorsement, compatibility, security, or release status? | |

## Verification

| Question | Record |
| --- | --- |
| What may the reader inspect and which evidence supports the claim? | |
| Which commands, environment, configuration, and dependencies produced it? | |
| Which checks passed, failed, or were skipped, and why? | |
| Is the evidence current for the claimed revision? | |
| What limitations and ownership boundaries apply? | |
| Who verified the claim and when? | |

## Metrics and Publication

| Field | Record |
| --- | --- |
| Metric, baseline, comparison period, data source, calculation, confounders if applicable | |
| Decision: publish, revise, hold, reject | |
| Approved wording, attribution, authority, and date | |
| Follow-up owner and next verification | |

Source tests do not prove clean installation; local configuration does not prove hosted enforcement;
a build is not publication. Link only to evidence accessible to the intended audience.
