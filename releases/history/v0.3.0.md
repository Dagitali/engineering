navigation, task briefs, and agent instructions.

## Highlights

See the [changelog] for the concise change list.

## Change Scope

The release adds `architecture/change-impact-map.md` for edits to this collection and
`testing/dependency-consistency.md` for package-manager-independent manifest, lock, and installation
review. Existing indexes and overviews link the new guidance.

Documentation guidance explains the roles of tutorials, guides, playbooks, runbooks, templates,
policies, and historical records. Task templates clarify review-only scope and workflow trust.
Contributor and maintenance guidance document the header convention. Agent instructions add
repository navigation, validation and release readiness, completion guidance, and reference links.

## Compatibility and Configuration

Additive guidance warrants a minor version under the [release policy]. Existing headings, links,
blank placeholders, local tool configuration, and historical records remain intact. No consumer
package manager, command set, directory layout, or branch model is mandated. Consumers review copied
instructions against their own contracts and adapt links before adoption.

## Support Boundary

Repository licensing and [support expectations] are unchanged. Static dependency comparison does not
prove installation, runtime compatibility, or dependency safety. Consumers retain ownership of
execution, tools, sensitive records, and adopted copies.

## Validation

Preparation checks on 2026-10-08 passed local Markdown destination and anchor validation with
`PYTHONPATH=../popo/src ../popo/.venv/bin/python -m popo check-docs --root .` and whitespace review
with `git diff --check`. These commands use the available sibling source environment and do not
establish a pinned validation environment for consumers.

The release documents receive a separate local link, reference, and whitespace review. Full
pre-commit execution is not recorded for this preparation. No application build or distribution
installation gate applies to this documentation collection. Checks describe preparation checkouts,
not an independently verified release tag.

## Deployment and Rollback

Use [release operations] for shared procedures. Adoption is a reviewed file update, not product
deployment or automatic consumer migration. Restore a consumer’s last known-good adaptations if
needed and verify local commands and links. Preserve existing tags and prepare follow-up
corrections.

## Known Limitations and Follow-Up

This record is prepared in released form at the user’s request. Its date is a release-document date,
not verified tag or publication metadata. No tag creation, hosted validation, publication, or
consumer rollout is performed by this preparation. Retain dated evidence for later delivery
separately.
